
# 🐳 Guia de Laboratório: Docker (Ambiente Compartilhado)

Nesta aula, todos estamos trabalhando no mesmo servidor. Para que ninguém sobrescreva o trabalho do colega, seguiremos a regra de ouro: **Tudo o que você criar deve ter o seu nome ou ID como prefixo.**

---

## 📋 Tabela de Variáveis

* **Seu ID:** `<SEU-NOME>` (ex: `joao`)
* **Sua Porta:** `<SUA-PORTA>` (ex: `8001`)

---

## 🛠️ Mão na Massa

### Passo 1: Execução simples (Foreground)

Vamos subir o Nginx com um nome específico. Se você não colocar `--name`, o Docker dará um nome aleatório.

```bash
# O nome do container será, por exemplo, 'joao-nginx-1'
docker run --name <SEU-NOME>-nginx-1 nginx

```

* 👉 **Teste:** Aperte `Ctrl + C` para parar. Como o terminal estava preso ao processo, o container para de rodar.

### Passo 2: Rodando nos bastidores (Background)

Agora vamos rodar sem travar o terminal, usando outro nome.

```bash
docker run -d --name <SEU-NOME>-nginx-2 nginx

```

* 👉 **Verifique o SEU container:**

```bash
# Isso vai listar todos, procure pelo seu nome na coluna 'NAMES'
docker ps

```

### Passo 3: O Desafio das Portas (Conectando ao Nginx)

No servidor compartilhado, a porta `80` do servidor só pode ser usada por **um** container. Cada um de vocês usará a porta atribuída pelo professor.

```bash
# Mapeando a sua porta exclusiva para a 80 interna do container
docker run -d --name <SEU-NOME>-web -p <SUA-PORTA>:80 nginx

```

* 👉 **Teste:** No seu terminal (ou navegador, se o IP for público), rode:

```bash
curl localhost:<SUA-PORTA>

```

### Passo 4: Alterando o site (Exec)

Vamos "entrar" no container e mudar o texto da página inicial.

```bash
docker exec -it <SEU-NOME>-web bash

```

Dentro do container:

```bash
echo "<h1>Sou o aluno <SEU-NOME> e este container e meu!</h1>" > /usr/share/nginx/html/index.html
exit

```

* 👉 **Verifique:** `curl localhost:<SUA-PORTA>`

### Passo 5: Persistência com Volumes

Se o professor rodar um comando para limpar todos os containers, você perde sua alteração. Vamos criar uma pasta só sua no servidor para salvar o site.

```bash
# Criando sua pasta no diretório /tmp do servidor
mkdir -p /tmp/site-<SEU-NOME>
echo "<h1>Site persistente do <SEU-NOME></h1>" > /tmp/site-<SEU-NOME>/index.html

# Remova o container antigo para liberar a porta e o nome
docker rm -f <SEU-NOME>-web

# Suba um novo usando o volume
docker run -d --name <SEU-NOME>-web -p <SUA-PORTA>:80 -v /tmp/site-<SEU-NOME>:/usr/share/nginx/html nginx

```

* 👉 **Reflexão:** Mesmo que o container seja apagado e recriado, seu arquivo em `/tmp/site-<SEU-NOME>` está seguro no disco do servidor.

### Passo 6: Redes Privadas e Isolamento

Vamos ver como dois containers seus podem conversar sem que outros alunos interfiram.

1. **Crie sua rede própria:**

```bash
docker network create rede-<SEU-NOME>

```

2. **Suba um Nginx nessa rede:**

```bash
docker run -d --name site-privado-<SEU-NOME> --net rede-<SEU-NOME> nginx

```

3. **Suba um segundo container (Alpine) na mesma rede para testar a comunicação:**

```bash
docker run -it --name terminal-<SEU-NOME> --net rede-<SEU-NOME> alpine sh

```

4. **Dentro do terminal do Alpine:**

```bash
# Instale o curl
apk add --no-cache curl

# Tente acessar o seu Nginx pelo NOME que você deu a ele
curl site-privado-<SEU-NOME>

```

---

## 🧹 Limpeza (Ao final da aula)

Para não deixar o servidor pesado, cada aluno deve remover seus brinquedos:

```bash
docker rm -f <SEU-NOME>-nginx-2 <SEU-NOME>-web site-privado-<SEU-NOME> terminal-<SEU-NOME>
docker network rm rede-<SEU-NOME>

```
