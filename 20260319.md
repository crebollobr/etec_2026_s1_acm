# 🐧 Aula: Sobrevivência no Linux e Sistemas de Arquivos

Bem-vindo(a) à nossa aula prática de Linux! Hoje vamos entender como o Linux se organiza, como descobrir quem somos no sistema, como monitorar o que está rodando e, finalmente, colocar a mão na massa criando e montando nosso próprio sistema de arquivos.

## 1. Onde eu estou? Descobrindo sua Distribuição Linux

Existem várias "versões" do Linux, chamadas de distribuições (ou *distros*), como Debian, Ubuntu, RedHat, Fedora, etc. Cada uma tem suas particularidades, então o primeiro passo de sobrevivência é saber onde você está pisando.

Para descobrir qual Linux você está usando, utilize os comandos:

```bash
# Mostra informações detalhadas sobre a distribuição
cat /etc/os-release

# Mostra informações sobre o kernel do Linux
uname -a
```

## 2. Quem sou eu? Identidade e Usuários

No Linux, permissões são fundamentais. Antes de fazer qualquer coisa crítica, você precisa saber com qual usuário está logado.

* `whoami`: Mostra o nome do seu usuário atual.
* `id`: Mostra não apenas o seu nome, mas o seu **UID** (User ID), o seu **GID** (Group ID) principal e de quais outros grupos você faz parte.

```bash
whoami
id
```
> **Nota:** O usuário supremo do sistema, que tem permissão para fazer qualquer coisa, chama-se `root` (UID 0). 

## 3. O que está acontecendo? Gerenciando Processos

Tudo o que está executando no seu computador é um "processo". Se o sistema estiver lento ou se você quiser saber o que está rodando nos bastidores, você pode listar esses processos.

* `ps aux`: Tira uma "fotografia" de todos os processos rodando no momento.
* `top` (ou `htop`, se instalado): Mostra os processos em tempo real, parecido com o Gerenciador de Tarefas do Windows. Pressione `q` para sair.

```bash
ps aux
```

## 4. O Mantra do Linux: "Tudo é um Arquivo"

No Linux, tudo o que o sistema interage é tratado como um arquivo. Isso inclui seus documentos de texto, diretórios, o teclado, o mouse e até mesmo os processos rodando na memória!



* **/proc**: Este diretório não existe no disco rígido. Ele é criado na memória RAM. Cada pasta numerada aqui dentro representa um processo rodando no sistema (`ps`). Se você ler o arquivo `/proc/cpuinfo`, verá informações sobre o seu processador!
* **/sys**: Semelhante ao `/proc`, mas focado em interagir com o hardware (kernel) do seu computador.

## 5. A Árvore do Sistema e o Superusuário

### O Diretório Raiz (`/`)
Diferente do Windows, que usa letras para os discos (`C:\`, `D:\`), o Linux coloca tudo debaixo de uma única árvore que começa na "raiz", representada pela barra `/`. 

### Dispositivos e o `/dev`
Lembra que "tudo é um arquivo"? Os seus discos rígidos, pendrives e partições também são! Eles ficam armazenados no diretório `/dev` (de *devices*). Um HD local geralmente aparece como `/dev/sda` ou `/dev/nvme0n1`.

### Montagem (Mount)
Para acessar o conteúdo de um disco (local ou de rede), você não clica duas vezes numa letra. Você precisa "pendurar" (montar) esse dispositivo de bloco (lá do `/dev`) em uma pasta vazia da sua árvore raiz. Esse processo se chama **Montar** (`mount`).

### O Comando Mágico: `sudo`
Montar discos, criar sistemas de arquivos ou alterar configurações do sistema são tarefas críticas. Lembra do usuário `root`? Só ele pode fazer isso. 
Para não precisarmos logar como root o tempo todo (o que é perigoso), usamos o comando `sudo` (SuperUser DO) antes do comando que queremos rodar, pegando os "poderes do root" emprestados por alguns minutos.

## 🛠️ Laboratório Prático: Criando e Montando um "Disco"

Neste laboratório, vamos criar um arquivo em branco, formatá-lo como se fosse um HD de verdade e montá-lo no nosso sistema! 

**Regra do Lab:** Substitua `SEU_NOME` pelo seu nome (sem espaços).

### Passo 1: Criar um arquivo vazio de 100MB
Vamos usar o comando `dd` (Data Duplicator) para copiar blocos vazios e criar um arquivo do tamanho desejado.

```bash
# Cria um arquivo de 100MB chamado SEU_NOME.img
dd if=/dev/zero of=SEU_NOME.img bs=1M count=100
```

### Passo 2: Formatar o arquivo
O sistema operacional precisa de um índice para saber como guardar arquivos lá dentro (um File System). Vamos usar o `ext4`, que é o padrão do Linux.

```bash
# Formata o arquivo como ext4
mkfs.ext4 SEU_NOME.img
```

### Passo 3: Criar um diretório (pasta) para servir de "ponto de montagem"
Precisamos de uma pasta vazia para pendurar o nosso novo disco.

```bash
# Cria a pasta
mkdir pasta_SEU_NOME
```

### Passo 4: Montar o sistema de arquivos
Agora vamos conectar o arquivo formatado à pasta que criamos. Como isso altera o sistema, precisamos do `sudo`!

```bash
# Monta o arquivo na pasta
sudo mount SEU_NOME.img pasta_SEU_NOME -o loop
```

### Passo 5: Verificar se funcionou
Vamos conferir o espaço em disco e verificar se o sistema reconheceu a nossa montagem.

```bash
# df mostra o espaço livre em disco (h = human readable)
df -h

# mount lista tudo que está montado (vamos filtrar com grep)
mount | grep SEU_NOME

# verificar o sistema de arquivos
cd pasta_SEU_NOME
df -h .

touch arquivo.txt

ls

# tem a pasta lost+found? quando tem um problema no disco, orquivos perdidos vão para essa pasta


```
*Se você rodar `df -h`, verá o seu arquivo de 100MB montado e pronto para uso!*

### Passo 6: Desmontar e Limpar
Terminou de usar o pen drive ou o disco? Nunca puxe direto, sempre desmonte antes para não corromper dados.

```bash
# Desmonta o diretório
sudo umount pasta_SEU_NOME
```

### Passo 7: Verificação Final
Rode os comandos de verificação novamente. O seu "disco" de 100MB não deve mais aparecer!

```bash
df -h
mount | grep SEU_NOME
```
