# Configurações de Rede e Armazenamento no Linux

Nesta aula, vamos colocar a mão na massa para entender como o Linux se comunica na rede e como consome armazenamento remoto. Sairemos da teoria abstrata e construiremos o roteamento e a conexão de dados na linha de comando, funcionando como verdadeiros detetives de rede.

---

## 1. O Ambiente de Laboratório

Para não dependermos das limitações físicas dos computadores locais, nosso laboratório usará o **QEMU**. Ele criará três micro máquinas virtuais levíssimas. 

A arquitetura da nossa rede será a seguinte:

```text
               [ Internet ]
                    | (eth0)
               [ micro02 ] (O Roteador / Firewall - 3 Placas)
            (eth1) / \ (eth2)
         [ micro01 ] [ micro03 ]
         (Cliente)   (Servidor NFS)
```



* **micro02:** É o coração da nossa rede. Diferente dos outros, ele possui **3 placas de rede** (uma para a internet, uma voltada para o cliente e outra voltada para o servidor). Ele fará o papel do roteador da nossa empresa.
* **micro01:** É a máquina do cliente. Ela nascerá sem nenhuma configuração de rede. Você terá que descobrir os IPs e configurar tudo nela do zero.
* **micro03:** É o nosso servidor de arquivos (Storage). Ele já possui a rede configurada e está exportando uma pasta na rede.

---

## 2. Teoria: Como funciona a Rede no Linux

Antes de configurarmos os comandos no laboratório, precisamos entender as engrenagens da rede no Linux.

* **Identificar a Placa de Rede:** O Linux usa nomes como `eth0` ou `eth1`. O comando `ip link` ou `ip addr` lista todas as placas conectadas ao sistema e seus endereços.
* **Endereço IP (A Identidade):** Para se comunicar, a máquina precisa de um endereço. Usamos o comando `ip addr add` para "injetar" um IP na placa de rede.
* **Gateway (A Porta de Saída):** O Gateway é o IP do roteador. É para onde o seu computador manda os pacotes quando tenta acessar uma rede externa (como a internet). Sem isso, a máquina só fala com quem está do lado dela.
* **DNS (O Tradutor):** Computadores usam IPs, mas humanos usam nomes (google.com). O arquivo `/etc/resolv.conf` é onde dizemos ao Linux qual servidor vai traduzir os nomes para nós.
* **IP Forwarding (Roteamento):** Por padrão, o Linux ignora pacotes que não são para ele. Habilitar o "Forward" é ligar uma chave dizendo: "A partir de agora, você é um roteador. Repasse os pacotes".
* **NAT (Network Address Translation):** A internet pública não sabe responder para um IP interno. O NAT disfarça o tráfego: pega o pacote interno, coloca o IP público do roteador e manda para a internet.

## 3. Prática: Descoberta de Rede e Conexão de Storage

Abra os terminais das suas três máquinas no QEMU. 

### Passo 1: Descoberta e Configuração do Cliente (`micro01`)

O `micro01` está completamente isolado. Vamos conectá-lo.

**1. A Descoberta do IP da Interface:**
Para dar um IP ao `micro01`, você precisa saber qual é a rede dele. 
* Vá até a tela do **`micro02`** (nosso roteador) e digite `ip addr`. 
* Procure pela interface `eth1` (que é a perna que liga ao `micro01`). Anote o endereço IP e a máscara de rede (ex: `/24`) que estão lá.
* Volte para o **`micro01`**. Você não pode colocar o mesmo IP do roteador! Mantenha os três primeiros blocos de números iguais e **escolha um número diferente para o último octeto** (por exemplo, `10`).

*Modelo do comando a ser executado no `micro01`:*
```bash
ip addr add <IP_ESCOLHIDO>/<MASCARA> dev <PLACA_DO_MICRO01>
ip link set <PLACA_DO_MICRO01> up
```

**2. A Descoberta do Default Gateway:**
Agora o `micro01` precisa saber por onde sair para a internet. A porta de saída é exatamente o IP do roteador que você acabou de investigar.
* Utilize o IP da interface `eth1` do `micro02` que você anotou no passo anterior.

*Modelo do comando a ser executado no `micro01`:*
```bash
ip route add default via <IP_DA_ETH1_DO_ROTEADOR>
```

**3. Configurar o DNS (Tradutor de Nomes):**
O `micro01` precisa saber traduzir "google.com". Vamos editar o arquivo responsável por isso usando o `nano`.
```bash
nano /etc/resolv.conf
```
Dentro do arquivo de texto, você deve adicionar a linha informando o IP de um servidor DNS público (como o do Google: `8.8.8.8`).
*Modelo da linha a ser inserida:*
```text
nameserver <IP_DO_DNS>
```
*(Salve apertando `Ctrl+O`, dê `Enter` e saia com `Ctrl+X`).*

**Testes de Conectividade:**
No `micro01`, tente executar:
* `ping 8.8.8.8` (Funciona?) -> **NÃO**.
* `ping google.com` (Funciona?) -> **NÃO**.
* `ping <IP_DO_MICRO03>` (Dica: vá no micro03 e dê um `ip addr` para descobrir o IP dele) -> **NÃO**.

> **Por que o ping não funciona?**
> Eles estão na rede local. Porém, quando o `micro01` tenta ir para a internet, ele entrega o pacote para o roteador (`micro02`), mas o roteador ainda está com o "motor" de encaminhamento desligado e joga o pacote fora.

---

### Passo 2: Ligando os Motores do Roteador (`micro02`)

Vá para a tela do **`micro02`**. Vamos ativá-lo para rotear a internet.

**1. Habilitar o IP Forwarding (Roteamento de pacotes):**
```bash
sysctl -w net.ipv4.ip_forward=1
```

**2. Habilitar o NAT (Mascaramento):**
Considerando que a interface conectada à internet no micro02 seja a `eth0`.
```bash
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
```

**Teste a Internet Novamente:**
Volte para o **`micro01`** e repita os testes:
* `ping 8.8.8.8` -> **Agora Funciona!** O pacote foi roteado.
* `ping google.com` -> **Agora Funciona!** O pacote foi roteado e o DNS traduziu o nome.

---

### Passo 3: Descoberta e Conexão do Armazenamento (NFS)

Com a rede funcionando, o `micro01` vai acessar o disco do **`micro03`**.

**1. Investigar o Servidor:**
Vá para a tela do **`micro03`** e use o comando `ip addr` para anotar o IP exato deste servidor.

**2. Descobrir os recursos no Cliente:**
Volte para o terminal do **`micro01`**. Vamos perguntar ao servidor o que ele tem disponível para nós usando o IP que você acabou de descobrir.
*Modelo de comando:*
```bash
showmount -e <IP_DO_MICRO03>
```
*(Ele deve listar a pasta que está sendo compartilhada).*

**3. Criar a "Porta de Entrada" local:**
Crie a pasta local que servirá de âncora para os arquivos da rede.
```bash
mkdir /mnt/nfs
```

**4. Montar o Recurso Remoto:**
Agora, faça a junção da pasta remota com a sua pasta local.
*Modelo de comando:*
```bash
mount -t nfs <IP_DO_MICRO03>:<CAMINHO_DA_PASTA_COMPARTILHADA> /mnt/nfs
```

Para confirmar, acesse o diretório com `cd /mnt/nfs` e dê um `ls`. Você acaba de construir uma rede roteada e anexar um storage de rede 100% via linha de comando!
