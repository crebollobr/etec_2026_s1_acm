## 🏗️ 1. Dockerfile Simples + Execução de Imagem Local

Até agora, você só baixou imagens prontas da internet. Vamos criar uma imagem **totalmente sua**.

### O Conceito de Tags e Versões

Quando baixamos uma imagem sem especificar a versão (ex: `docker pull ubuntu`), o Docker joga a tag `:latest` (última versão) automaticamente.

* **Perigo do `:latest`:** Em produção, se a imagem da internet atualizar e mudar o código interno, sua aplicação pode quebrar do nada.
* **Boa prática:** Travar a versão usando tags explícitas (ex: `:alpine`, `:3.12`, `:22.04`).

Vamos criar uma receita de imagem customizada. Primeiro, crie a pasta do teste e entre nela:

```bash
mkdir -p /tmp/minha-imagem && cd /tmp/minha-imagem

```

Salve o conteúdo abaixo como `index.html` (dentro de `/tmp/minha-imagem`):

```html
<h1>Minha Imagem Customizada Local!</h1>
```

Salve o conteúdo abaixo como `Dockerfile` (na mesma pasta):

```dockerfile
FROM nginx:alpine
COPY index.html /usr/share/nginx/html/index.html
```

Agora, vamos buildar (construir) a imagem e dar o nome de `meu-nginx:1.0` (repare no ponto `.` no final, ele indica o diretório atual):

```bash
docker build -t meu-nginx:1.0 .

```

Veja que a imagem agora está listada localmente no seu computador:

```bash
docker images

```

> **Olha o destaque:** Essa imagem não existe no Docker Hub da internet. Ela é **sua**.

Rode o contêiner a partir da sua imagem:

```bash
docker run -d --name meu-site -p 80:80 meu-nginx:1.0

```

Teste no terminal: `curl localhost:80` (Limpe o contêiner após testar: `docker rm -f meu-site`).

## 🎼 2. Seu Primeiro Arquivo `docker-compose.yaml` Simples

Ficar digitando parâmetros no `docker run` toda hora cansa. O **Docker Compose** serve para declarar o que você quer em um arquivo estruturado em **YAML**.

Salve o conteúdo abaixo como `docker-compose.yaml` (na mesma pasta):

```yaml
services:
  meu-servidor:
    image: nginx:alpine
    ports:
      - "80:80"
```

Para subir a infraestrutura declarada, usamos um único comando:

```bash
docker compose up -d

```

Para derrubar tudo o que foi criado por esse arquivo:

```bash
docker compose down

```

## 🔄 3. Automatizando a Aula Passada (Nginx + PHP com Compose)

Na aula do dia 25/05, nós criamos uma pasta local, um arquivo de configuração para o Nginx (`default.conf`), criamos uma rede chamada `app-net` e subimos dois contêineres separados que se comunicavam pelo nome.

Veja como o Docker Compose resolve toda aquela trabalheira em poucas linhas, criando a rede interna e os mapeamentos automaticamente.

Prepare a estrutura de pastas no host para simular o ambiente:

```bash
mkdir -p /tmp/antigo/app
mkdir -p /tmp/antigo/config

```

Salve o conteúdo abaixo como `index.php` dentro de `/tmp/antigo/app/`:

```php
<?php phpinfo(); ?>
```

Salve o conteúdo abaixo como `default.conf` dentro de `/tmp/antigo/config/`:

```nginx
server {
    listen 80;
    root /var/www/html;
    index index.php;
    location ~ \.php$ {
        fastcgi_pass php-fpm:9000; # Nome do serviço do compose
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME /var/www/html$fastcgi_script_name;
        include fastcgi_params;
    }
}
```

Entre na pasta do projeto:

```bash
cd /tmp/antigo

```

Agora, salve o conteúdo abaixo como `docker-compose.yaml` dentro de `/tmp/antigo/` (ele junta as duas peças: Nginx + PHP):

```yaml
services:
  web-nginx:
    image: nginx:alpine
    ports:
      - "80:80"
    volumes:
      - ./app:/var/www/html
      - ./config/default.conf:/etc/nginx/conf.d/default.conf
    depends_on:
      - php-fpm

  php-fpm:
    image: php:8.2-fpm
    volumes:
      - ./app:/var/www/html
```

Suba o ambiente integrado:

```bash
docker compose up -d

```

**Por que usamos isso?** Porque com o comando `docker compose up -d`, o Docker lê o arquivo, cria uma rede isolada automaticamente, linka o Nginx com o PHP-FPM usando DNS interno e monta os volumes sem você precisar digitar comandos infinitos.

Derrube o ambiente antes de prosseguir:

```bash
docker compose down

```

## 🛠️ 4. Imagem Personalizada Dentro do Docker Compose

Podemos misturar o **Passo 1** com o **Passo 2**. Se precisarmos que um dos serviços do compose use uma imagem customizada construída por nós na hora, trocamos a linha `image:` pela instrução `build: .`.

Salve o conteúdo abaixo como `docker-compose.yaml`:

```yaml
services:
  web:
    build: . # O compose vai caçar o 'Dockerfile' nesta pasta, compilar e subir
    ports:
      - "80:80"
```

## 🧪 Atividade 1: Imagem Customizada PHP com Extensão Gráfica (GD)

**Objetivo:** O PHP padrão do Docker Hub não vem com suporte para manipulação e geração de imagens do sistema (biblioteca gráfica GD). Você deve construir uma imagem personalizada do PHP com essa extensão instalada, criar uma página web que consome um script PHP dinâmico e orquestrar tudo usando o Docker Compose.

### 📋 Códigos fornecidos pela Engenharia:

#### 1. Estrutura de pastas do seu projeto:

```bash
mkdir -p /tmp/projeto-gd && cd /tmp/projeto-gd

```

#### 2. O arquivo principal (`index.html`):

Ele apenas consome o arquivo PHP como se fosse uma imagem estática de mercado.

Salve o conteúdo abaixo como `index.html`:

```html
<!DOCTYPE html>
<html lang="pt-br">
<head>
    <meta charset="UTF-8">
    <title>Docker PHP GD</title>
</head>
<body>
    <h1>Exibindo imagem gerada dinamicamente pelo PHP via Docker:</h1>
    <br>
    <img src="img.php" alt="Nome Estilizado">
</body>
</html>
```

#### 3. O arquivo gerador de imagens (`img.php`):

Este script usa funções exclusivas da extensão `gd`. Se rodar no PHP padrão, a aplicação quebra. Ele imprime o nome estilizado em uma caixa colorida.

Salve o conteúdo abaixo como `img.php`:

```php
<?php
header("Content-Type: image/png");

$nome = "Carlos"; // Variável solicitada

// Cria uma tela de 300x100 pixels
$imagem = imagecreate(300, 100);

// Cores (A primeira cor define o fundo da imagem)
$corFundo = imagecolorallocate($imagem, 41, 128, 185); // Azul escuro
$corTexto = imagecolorallocate($imagem, 255, 255, 255); // Branco

// Escreve o texto estilizado na tela (Fonte tamanho 5, posições X=80, Y=40)
imagestring($imagem, 5, 80, 40, "Ola, " . $nome, $corTexto);

// Renderiza o arquivo como PNG
imagepng($imagem);
imagedestroy($imagem);
?>
```

### 🛠️ O que você deve fazer:

1. **Criar o `Dockerfile`:** Você usará a imagem base `php:8.2-apache` (que já vem com o servidor web embutido na porta 80). Dentro dele, você deve rodar o comando Linux para instalar as dependências de sistema e habilitar a extensão gráfica.
* *Dica do comando de instalação de extensão nativo do PHP:*
```dockerfile
RUN apt-get update && apt-get install -y libpng-dev && docker-php-ext-install gd

```


* Adicione a instrução para copiar os arquivos `index.html` e `img.php` para dentro do diretório padrão do Apache interno: `/var/www/html/`


2. **Criar o `docker-compose.yaml`:** Monte um arquivo simplificado onde o serviço construa o seu Dockerfile local e exponha a porta `80:80`.
3. **Testar no navegador:** Suba o ambiente com o Compose e use o menu de portas (Traffic Ports -> 80) do Killercoda para validar se a imagem azul com o texto "Ola, Carlos" é exibida com sucesso na tela.

## 🎯 Desafio 1: Dockerizando um Servidor Node.js na Raça

**Cenário:** O desenvolvedor front-end da empresa criou um protótipo de site utilizando **Node.js** puro (Javascript rodando fora do navegador). Ele te entregou o arquivo de script e disse: *"Na minha máquina funciona, agora joga isso para rodar em contêiner"*.

### 📋 Código do arquivo (`servidor.js`):

Crie uma nova pasta isolada para este desafio:

```bash
mkdir -p /tmp/desafio-node && cd /tmp/desafio-node

```

Salve o conteúdo abaixo como `servidor.js`:

```javascript
const http = require('http');

const server = http.createServer((req, res) => {
  res.writeHead(200, {'Content-Type': 'text/html; charset=utf-8'});
  res.end('<h1>🚀 Desafio Concluido! Servidor Node.js respondendo perfeitamente dentro do Docker!</h1>');
});

// O site escuta internamente na porta 3000
server.listen(3000, () => {
  console.log('Servidor rodando na porta 3000');
});
```

### 📋 Procedimento de Execução Manual (Como funciona na máquina real):

Para rodar esse script na linha de comando de um computador comum, o operador precisa ter o Node instalado e rodar o comando:

```bash
node servidor.js

```

### 🛠️ Sua Missão DevOps:

1. **Fazer o Build na Linha de Comando (Dockerfile):** Escreva um `Dockerfile` customizado para essa aplicação.
* Use como base a imagem oficial do Node em formato leve: `FROM node:18-alpine`
* Defina o diretório de trabalho interno (`WORKDIR`).
* Copie o arquivo `servidor.js` para dentro do contêiner.
* Informe a porta interna que a aplicação usa (`EXPOSE`).
* Defina o comando de inicialização padrão (`CMD`) baseado no procedimento de execução manual listado acima.


2. **Colocar no Docker Compose:** Monte um `docker-compose.yaml` para gerenciar esse contêiner. Lembre-se que o usuário externo quer acessar o site digitando a porta padrão web `80` no navegador, mas o script do Node roda internamente na porta `3000`. Faça o redirecionamento correto de portas (`host:container`).
3. **Testar:** Suba a aplicação usando o comando do Compose e verifique o resultado abrindo a porta `80` no menu do Killercoda.
