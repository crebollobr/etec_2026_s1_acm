## Teoria Detalhada: Do Hardware à Nuvem

### 1. Sistemas Operacionais no Hardware (Bare Metal)
O termo **Bare Metal** (metal nu) refere-se à arquitetura tradicional onde um sistema operacional é instalado diretamente no hardware físico (disco rígido, placa-mãe, processador), sem intermediários.
* **Como funciona:** O Sistema Operacional (SO) é o dono absoluto da máquina. Ele gerencia a memória, os processos e a rede diretamente.
* **Vantagens:** Performance máxima. Como não há intermediários, 100% do poder da máquina é dedicado àquele SO e suas aplicações.
* **Desvantagens:** Desperdício de recursos e inflexibilidade. Se você tem um servidor superpotente rodando apenas um pequeno site, 90% da capacidade da máquina ficará ociosa, gastando energia elétrica à toa.
* **Exemplo:** O seu computador pessoal em casa ou servidores dedicados de altíssimo desempenho para bancos de dados.

### 2. Virtualização e Hipervisores 
Para resolver o problema do desperdício do Bare Metal, surgiu a virtualização. Ela permite "fatiar" um servidor físico poderoso em vários servidores menores e virtuais. Para isso, usamos um software chamado **Hipervisor**. O Hipervisor atua como um "maestro", enganando os sistemas operacionais virtuais e fazendo-os acreditar que possuem hardware físico próprio.

* **Hipervisor Tipo 1 (Nativo ou Bare-Metal):** É o padrão da indústria para Data Centers (Nuvem). O Hipervisor é instalado *diretamente no hardware*, substituindo o sistema operacional tradicional. Ele é extremamente rápido e focado apenas em gerenciar as Máquinas Virtuais (VMs).
    * *Exemplos:* VMware ESXi, Microsoft Hyper-V, Proxmox.
* **Hipervisor Tipo 2 (Hospedado):** É o padrão para uso pessoal. Você já tem um sistema operacional rodando (como o Windows 11) e instala o Hipervisor como um programa comum. Ele é mais lento que o Tipo 1, pois precisa pedir recursos ao seu Windows antes de repassar para a VM.
    * *Exemplos:* Oracle VirtualBox, QEMU, VMware Workstation.

### 3. Emuladores vs. Virtualizadores (O Caso do QEMU)
Na nossa prática, usaremos o **QEMU**. Ele é uma ferramenta poderosa porque atua em duas frentes:
* **Emulador:** Ele consegue "traduzir" instruções de processadores diferentes. Por exemplo, você pode rodar um sistema feito para processadores de celular (ARM) dentro do seu computador Intel (x86). Isso exige muito processamento.
* **Virtualizador:** Quando usado na mesma arquitetura (Intel no Intel), ele atua junto com tecnologias do sistema hospedeiro para entregar uma performance quase nativa, funcionando como um excelente Hipervisor Tipo 2.

### 4. Máquinas Virtuais (VMs) vs. Contêineres 
Hoje, existem duas formas principais de isolar aplicações:
* **Máquinas Virtuais (VMs):** Simulam o hardware completo. Se você cria uma VM, precisa instalar um Sistema Operacional Inteiro (Guest OS) nela, reservar memória RAM fixa e espaço em disco.
    * *Analogia:* É como construir uma **casa isolada** em um terreno. Ela tem sua própria fundação, encanamento e rede elétrica. É muito seguro, mas gasta muito material.
* **Contêineres (ex: Docker):** Não virtualizam o hardware. Eles "pegam carona" no núcleo (Kernel) do sistema operacional que já está instalado, isolando apenas a aplicação e suas dependências. Um contêiner liga em milissegundos e consome apenas os megabytes que o aplicativo precisa.
    * *Analogia:* É como alugar um **apartamento em um prédio**. Todos os apartamentos (contêineres) compartilham a mesma fundação, encanamento e portaria (Kernel do SO hospedeiro), mas cada morador tem sua privacidade.

### 5. Orquestração
Imagine gerenciar 5.000 contêineres do iFood em uma sexta-feira à noite. Se um travar, quem reinicia? Se os pedidos aumentarem, quem cria novos contêineres? É aí que entra a **Orquestração**. Softwares como o **Kubernetes** monitoram o ambiente e tomam decisões automáticas (aumentar recursos, reiniciar máquinas falhas) para manter os serviços sempre no ar.

## Prática: Instalação do Alpine Linux via QEMU

Para a nossa atividade, vamos utilizar o **QEMU** para rodar uma máquina virtual extremamente leve baseada no **Alpine Linux** (um sistema focado em segurança e minimalismo, muito usado no mundo dos contêineres). Todo o acesso será via terminal (linha de comando).

### Passo a Passo

1. **Preparação dos Arquivos:**
   * Certifique-se de ter baixado e extraído o arquivo `qemu_instalacao.zip` no seu computador.
2. **Acessando a Pasta:**
   * Abra o Prompt de Comando do Windows (Pesquise por `cmd` no Menu Iniciar).
   * Utilize o comando `cd` (Change Directory) para navegar até a pasta onde você extraiu os arquivos.
   * *Exemplo:* Se estiver em Downloads, digite: `cd Downloads\qemu_instalacao`
3. **Iniciando a Instalação:**
   * Dentro da pasta, digite o seguinte comando e aperte Enter:
     ```cmd
     instalacao.bat
     ```
   * A janela do QEMU se abrirá. **Aguarde as instruções do professor** para realizar as configurações iniciais de disco, rede e senha do root no Alpine Linux.
4. **Desligando Corretamente:**
   * Após o professor confirmar que a instalação foi concluída com sucesso, **não feche a janela no "X"**.
   * No terminal do Alpine, digite o comando abaixo para desligar o sistema operacional de forma segura:
     ```bash
     halt
     ```
   * Aguarde a janela do QEMU fechar sozinha ou avisar que o sistema foi paralisado.
5. **Rodando a Máquina Definitiva:**
   * De volta ao seu `cmd` do Windows, vamos ligar a máquina a partir do disco já instalado (e não mais do instalador). Digite:
     ```cmd
     rodar.bat
     ```
6. **Validação da Prática:**
   * Quando o Alpine terminar de carregar, faça o **login** com o usuário `root` e a senha que você configurou com o professor.
   * Assim que acessar o sistema e ver o prompt do terminal (ex: `localhost:~#`), **tire um Printscreen (captura de tela)** mostrando que você conseguiu logar com sucesso. Salve a imagem para envio.
